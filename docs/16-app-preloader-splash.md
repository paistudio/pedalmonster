# App Preloader / Splash Overlay

## Goal
Show a custom full-screen overlay every time the app is loaded or refreshed, covering the page while critical resources (JS bundle, fonts, initial route/mock data) load, so the user never sees a blank flash or a half-rendered shell. The overlay plays a short **logo build animation** — the bicycle pedal appears first, then the monster claw sweeps in and grips it to complete the mark — and closes once the animation has finished **and** the app is ready to render, whichever takes longer.

This is distinct from the native PWA splash screen (from `manifest.json`, OS-controlled, only shown when launched from an installed home-screen icon). This overlay is a custom in-page element that works on every load, including a plain browser-tab refresh. See `design.md` → "Preloader / Splash Overlay" for the visual spec.

## The Logo, Decomposed
`assets/image/pedalmonster-logo-icon.svg` is a single `<path>` (viewBox `0 0 1254 1254`, `fill-rule="evenodd"`) made of **16 subpaths**, each starting with an `M` command. Those subpaths separate cleanly into the two halves of the mark — this decomposition is what makes the animation possible, and it has been verified by rendering each group in isolation. Split the `d` attribute on `M` and regroup by index:

| Group | Subpath indices (0-based) | What it is |
|---|---|---|
| **Pedal** | `0, 2, 8, 9, 10, 11, 12, 13, 14, 15` | The platform pedal: cage, axle/spindle stub on the right, bolt heads and their holes |
| **Claw finger A** | `1, 5` | Largest finger + knuckle mass (right side) |
| **Claw finger B** | `3, 6` | Middle finger |
| **Claw finger C** | `4, 7` | Leftmost/outermost finger |

Each group is rendered as its own `<path>` with `fill-rule="evenodd"` so its inner detail cut-outs (the odd indices above: 2, 5, 6, 7, and the bolt holes 13–15) stay as holes rather than becoming solid blobs. Concatenating all four groups' `d` strings back together in any order reproduces the original mark exactly — nothing is redrawn or approximated.

**Do not re-trace or hand-edit the path data.** Derive the four groups programmatically from the source SVG at build time (or paste the derived groups into `index.html` once, generated by a script) so the logo asset stays the single source of truth.

## Animation Spec
Three stages, ~1050ms to a fully formed logo. All motion uses CSS transforms/opacity only (no morphing library, no JS animation loop) with `transform-box: view-box` so `transform-origin` can be given in viewBox user units.

**Stage 1 — Pedal lands (0–500ms).**
The pedal group fades in from `opacity: 0`, rising and scaling up: `translateY(70px) scale(0.9)` → none, over 500ms on `cubic-bezier(.2,.7,.3,1)`, `transform-origin: 620px 900px`. It reads as the pedal settling into place on its own — a complete, recognizable shape before the claw exists.

**Stage 2 — Claw grips (340–1040ms).**
The three finger groups sweep down from the upper-left and clamp onto the pedal. Each finger animates `translate(-90px, -230px) rotate(-19deg) scale(1.05)` + `opacity: 0` → resting state, 520ms on `cubic-bezier(.25,.8,.3,1.05)`, with a shared `transform-origin: 960px 600px` (the wrist, where the claw meets the pedal) so they rotate in as one hand closing rather than sliding in as separate pieces.
Stagger the starts so the fingers land in sequence: **A at 340ms, B at 430ms, C at 520ms** (90ms apart). Finger A is the innermost/largest, so it lands first and the outer fingers wrap over it.

**Stage 3 — Grip settle (950–1250ms).**
The whole logo group does one quick impact pulse — `scale(1)` → `scale(1.045)` at 45% → `scale(1)` — over 300ms, `ease-out`, `transform-origin: 620px 700px`. This sells the claw clamping shut and marks the animation as finished.

**Idle hold.** If the app still isn't ready after Stage 3, the completed logo holds with a subtle low-amplitude opacity pulse (loop) so the screen never looks frozen. No spinner, no progress bar, no loading text — the logo's own motion is the only indicator.

**Reduced motion.** Under `@media (prefers-reduced-motion: reduce)`, skip stages 1–3 entirely and show the completed logo with a plain opacity fade-in; dismissal logic is unchanged.

## Required Behavior
- The overlay markup lives directly in `index.html` (not inside the Vue app), so it paints before Vue, the router, or any JS bundle finishes loading — this is what makes it cover the resource-loading gap, not just app-mount time.
- Full-viewport, fixed position, `{colors.canvas}` (#0a0a0a) background, logo centered at ~150px wide, white fill (`{colors.ink}`).
- The SVG is **inlined** into `index.html` (not an `<img>` or a CSS `background-image`), because the four groups must be individually targetable by CSS and it avoids an extra network request on the critical path.
- The logo asset currently lives at repo root `assets/image/pedalmonster-logo-icon.svg`, outside the `frontend/` app — it needs to be brought into the frontend (copied into `frontend/src/assets/` or read by a small build step) as part of this work.
- **Minimum display duration**: the overlay stays visible for at least the full animation (~1050ms to formed, ~1250ms including settle) even if the app becomes ready sooner — it must never flash for a few ms. If the app takes longer, the idle hold covers the wait.
- **Dismissal**: once both conditions are met (animation finished *and* Vue app mounted with first route rendered), the overlay fades out (opacity, 250–350ms) and removes itself from the DOM — not just `display: none`, so its animations and timers stop.
- **Failsafe**: a hard 8000ms timeout dismisses the overlay regardless of app state, so a boot failure can never leave the user staring at a permanent splash screen.
- The minimum duration must not block the page from becoming interactive underneath; it exists only to avoid a jarring flash, not to artificially delay every load.

## Implementation
| File | Role |
|---|---|
| `frontend/src/assets/pedalmonster-logo-icon.svg` | The logo, copied in from repo-root `assets/image/` so the frontend builds standalone. Single source of truth — never hand-edit the derived groups instead of this. |
| `frontend/build/preloader-logo.js` | Vite plugin. Reads the SVG, splits the `d` on `M`, regroups by the index map above, and replaces the `%PRELOADER_LOGO%` placeholder in `index.html` via `transformIndexHtml`. Throws if the subpath count is no longer 16, so a re-exported logo fails the build loudly instead of rendering a broken mark. |
| `frontend/index.html` | Overlay markup, all animation CSS, and the inline dismissal script (`window.__pmAppReady`, `MIN_MS`, `MAX_MS`). |
| `frontend/src/main.js` | Calls `window.__pmAppReady()` after `router.isReady()`, i.e. once the first route has resolved. |

## Interaction Rules
- No user interaction while the overlay is visible (no dismiss button, no tap-to-skip for MVP).
- The overlay reappears on every full page reload (it sits outside Vue's SPA lifecycle) but must **not** reappear on client-side route navigation. It is not a route-transition loader — that is out of scope here.

## Acceptance Criteria
- On a hard refresh, the near-black overlay is the first and only thing visible — no flash of unstyled content or blank page before it.
- The pedal is clearly recognizable on its own before any claw appears; the claw then visibly sweeps in and closes onto it, finishing as the exact logo mark with no visual seams or misalignment against the original SVG.
- The finished mark is pixel-identical to `pedalmonster-logo-icon.svg` — the split into four groups introduces no gaps, doubled edges, or filled-in holes.
- Overlay never displays for less than the animation duration, and never hangs indefinitely once the app is ready — it always resolves.
- Overlay does not reappear when navigating between routes inside the app.
- Under `prefers-reduced-motion: reduce`, the logo appears with a fade only, and still dismisses correctly.
- Works at 375–430px mobile viewport (the only target — no desktop-specific sizing).

## Best-Practice Decisions
- **Narrative build animation, not a shape morph.** A true point-to-point morph (blob → logo) would need either a hand-drawn second path with matching point counts or a runtime interpolation library (e.g. Flubber), and on a path this detailed it tends to produce writhing artifacts mid-tween. Splitting the existing mark into its real semantic parts — pedal, then claw — tells a better brand story ("pedal, then monster") and uses only CSS transforms on the untouched original geometry. It is cheaper, more robust, and on-brand.
- **Grouped by meaning, verified visually.** The index groupings above were confirmed by rendering each group in isolation; the pedal group stands alone as a complete pedal and the claw groups as complete fingers. Don't reshuffle indices without re-checking the render, since the inner cut-outs must stay with their parent shape or holes will fill in.
- **Overlay in `index.html`, not a Vue component.** A Vue-mounted overlay can only appear after the JS bundle has downloaded and executed — it would miss exactly the loading window it is meant to cover. Plain HTML/CSS plus a small inline `<script>` is the only way to paint before that point.
- **Removal, not hide.** The overlay element is removed from the DOM on dismissal to fully stop its CSS animations and avoid lingering repaint cost, since it is a one-time-per-load element.
- **No skip/tap-to-dismiss for MVP**, matching the project's MVP-scope discipline (see `00-project-overview.md`) — add only if testing calls for it.
